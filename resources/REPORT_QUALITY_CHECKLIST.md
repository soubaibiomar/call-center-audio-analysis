# Per-step documentation acceptance checklist

- [ ] Actual upstream revision and final worktree SHA recorded.
- [ ] Real before/after comparison with paths, functions and behavior.
- [ ] Plain-language purpose and result grounded in execution.
- [ ] File inventory includes created/changed/kept with explanation.
- [ ] Important code explained line-by-line or in short logical blocks.
- [ ] Every newly added import explained (origin, symbol, purpose, version).
- [ ] Concepts explained for beginners with one runnable/traceable example.
- [ ] PII, permissions, data/model lineage, security and failure modes considered.
- [ ] Exact verification commands, exit codes, pass/fail/skip and evidence.
- [ ] Numeric metrics include unit, sample size, baseline and environment; no fake measurements.
- [ ] At least five Q&As **answered**, including a failure/tradeoff item.
- [ ] Risks, unanswered questions, follow-up dependencies and handoff commands.
- [ ] No claims of completing scientific model improvement without actual fine-tuning and held-out benchmark.
