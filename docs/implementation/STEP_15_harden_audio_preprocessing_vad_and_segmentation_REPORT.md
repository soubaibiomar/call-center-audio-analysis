## 4. Code, control flow and errors

`decode_resample` calls the existing size/magic/metadata validation, pins the expected demuxer for WAV/MP3/FLAC/M4A, opens bytes in memory through `av.open`, requires one audio stream and one or two channels, then creates an `AudioResampler` in planar float32 at 16 kHz. Every decoded and flushed frame contributes to a hard 600-second limit before concatenation. Empty decode, invalid channels, non-finite samples and decoder exceptions fail explicitly. The optional limit is lower than the existing one-hour intake limit: longer calls still use the default path. The operation is in-memory and can temporarily hold multiple copies; it is not a streaming implementation.

`AudioChunk` represents a half-open range `[start_sample, end_sample)` and converts bounded relative seconds to the original recording time. `speech_chunks` averages channels only for its temporary VAD input, uses the faster-whisper bundled Silero ONNX model, validates returned bounds and splits long spans without changing sample positions. For example, a chunk starting at sample 8000 at 16 kHz starts at 0.5 seconds; a 0.1-second relative ASR timestamp maps to 0.6 seconds. This mapping is applied before `align_turn`, which continues to use the unmodified recording timeline. A segment outside its chunk or with inverted endpoints raises instead of silently shifting evidence. A chunked ASR request uses `vad_filter=False` because VAD already selected the samples. The existing audio-only cache is bypassed for chunked mode because it does not encode preprocessing configuration.

## 6. Concepts

A codec compresses or encodes samples, while a container packages streams and metadata: MP3 and AAC audio can require different decoders even when their filenames are misleading. FFmpeg decodes to numerical samples; resampling changes the number of samples per second, not the intended duration. At 48 kHz one second contains 48,000 samples; at 16 kHz it contains 16,000. Channel order can carry verified agent/customer provenance and must not be discarded. VAD proposes speech intervals and can omit quiet speech; it is not ground truth. Keeping integer sample indices until timestamp conversion prevents accumulated chunk-boundary rounding drift. Denoising can reduce noise while also altering speech or adding delay.

## 10. Questions and answers

1. **Why VAD?** It can skip silence, but quiet speech may be missed; this is why the sample recall is reported and the new path is optional.
2. **Why use integer samples for chunks?** Adjacent chunks share exact endpoints, and the absolute offset preserves alignment with original diarization and citations.
3. **Does stereo imply which side is the agent?** No; role mapping requires separately trusted metadata, as in STEP_14.
4. **Is denoising always beneficial?** No. It introduces distortion and delay, and the measured small SNR change is not proof of better speech recognition.
5. **What happens to corrupt or unsupported audio?** The tested validation or decoder path raises a clear error; decoder isolation and comprehensive malicious-media coverage remain open.
6. **Why skip the old cache?** Its key does not distinguish preprocessing or VAD settings, so reuse could return stale results.
7. **Does 0 missed seconds prove VAD is safe?** No; one English media recording cannot characterize accents, quiet speech, music or telephone noise.
