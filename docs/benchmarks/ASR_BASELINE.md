# ASR baseline and benchmark protocol — STEP13

Status: provisional evaluation tooling; no deployment selection from telephone evidence. The original `src/agents/transcription.py` continues to use faster-whisper and retains its existing behavior. `src/datasets/asr_benchmark.py` provides common adapters and aggregate metrics for an offline validation experiment; `scripts/benchmark_asr.py` runs only the local validation partition. This experiment is not an authenticated production benchmark service.

The user-supplied [Kaggle Call Center Data](https://www.kaggle.com/datasets/satvicoder/call-center-data) is a CC0 daily performance table: the API v1 archive contains a single CSV, not recordings or transcripts. It cannot be used to measure ASR. [French telephone corpus sample listing](https://huggingface.co/datasets/ud-nlp/french-speech-recognition-dataset) advertises audio/text but its current repository tree provides only a CSV and README; the license shown is CC BY-NC-ND and the card does not establish individual transcript verification or this project's rights. [AxonData French call-center listing](https://huggingface.co/datasets/AxonData/french-call-center-speech-dataset) provides sample audio but the full commercial dataset requires a license and the visible sample metadata does not establish reviewed reference transcripts. [Defined.ai's French telco dataset](https://defined.ai/datasets/european-french-spontaneous-dialogue-telco) describes human transcription, but access is by quote/sample request; its exact project license is not established. None was imported or used.

The interim inputs are two Common Voice 22 French read-speech clips from the project's STEP12 validation partition. Their source names indicate the original Common Voice *test* subset, so this is not a claim that the source corpus's own held-out set remains untouched. The project's independently created local test partition was not used. The two items are far too few and outside the target telephone domain, and cannot justify selecting or approving a model. Source-voted labels are not a separate project transcript audit.

Policy is NFC normalization, Unicode case-folding and whitespace folding, with punctuation and diacritics retained. WER and CER use total Levenshtein errors divided by total reference words and characters, respectively; whitespace counts as a CER character. Latency includes per-clip transcription and decoding but excludes model load; percentiles are nearest-rank. RTF is summed inference latency divided by summed audio duration. Failed clips contribute to failure rate but not accuracy; missing GPU memory is `null`, not zero. Code-switch recordings need span-level references and are rejected by this smoke-test runner. WER/CER can exceed 1.0.

The local result contains dataset/lock, audio, reference and model content hashes and source IDs, and stays under the ignored dataset directory. References and predictions are not printed or logged. For real evaluation, independently protect the frozen reference files and lock/checksum, pre-register the comparison settings, validate consent/retention at execution time, use verified speaker-disjoint telephone audio, report uncertainty and failures, and run under controlled GPU load. Never tune on the project's locked test set. Adjacent checksum files and local operator attestations are not a governance or security boundary.

## User-supplied UniData call-center preview

[Kaggle: unidpro/call-center-audio](https://www.kaggle.com/datasets/unidpro/call-center-audio), v1, lists five FLAC recordings and two CSV files (48,550,483 bytes total). Its `metainfo.csv` has five records, each matching a listed recording and containing a transcription field. Only metadata was read; transcript text was neither stored nor reproduced. Kaggle identifies the preview license as CC BY-NC-ND 4.0: it is non-commercial and does not establish the rights for commercial project use. The [provider](https://unidata.pro/datasets/call-center-audio/) states that its samples are for testing and validation and sells the full dataset, but the source pages do not establish that the five transcripts were independently human-reviewed or give speaker linkage sufficient to prove disjoint splits. Its stated full-corpus composition is predominantly English, not evidence of French or Darija coverage for these five calls. The sample is a promising restricted candidate, but has not been approved as gold or imported into STEP12. Verify actual source provenance, applicable use, data consent/privacy, transcript review and speaker separation before using it for an evidence-based telephone benchmark. Inventory evidence: `docs/implementation/evidence/step13-20261028/kaggle-audio-inventory.json`.

## Further source search

[ALAMA Moroccan Arabic audio](https://github.com/Ackanel/alama_audio_dataset) describes three independent human transcribers and Darija/French loan words. Its repository page does not show a dataset license, speaker identifiers or a held-out partition, so permission and leakage review remain necessary; it is not established as telephone audio. [Darija ASR Corpus](https://huggingface.co/datasets/abnajlae/darija-asr-corpus) documents per-subset licenses and speaker identifiers, but the review status, recording context, reference integrity and conditions must be verified per record; it is not a verified telephone benchmark. The [OrienTel Morocco catalogue](https://catalogue.elra.info/en-us/repository/browse/ELRA-S0183/) describes 772 Moroccan speakers recorded by telephone but includes prompted numbers and other potentially sensitive utterances; access, specific licensing and fitness for customer-call evaluation are not established. [Defined.ai French telco data](https://defined.ai/datasets/european-french-spontaneous-dialogue-telco) explicitly describes human transcription, but access requires a quote or sample request. None of these candidates was acquired or approved.

## Additional user-supplied AxonData sources

[AxonData English contact-center sample](https://huggingface.co/datasets/AxonData/english-contact-center-audio-dataset) contains two English MP3s and two DOCX documents in its repository tree. [AxonData multilingual Kaggle sample](https://www.kaggle.com/datasets/axondata/call-center-speech-dataset) lists ten MP3s and ten DOCX documents, including two French folders, under CC BY-NC 4.0. Each of the two French DOCX files was opened in memory and contains nonempty text; text was not retained. Association is by parent folder, not verified alignment; notably one French audio filename contains the other French sample's identifier, which needs investigation before trusting the pairing. The source card does not establish human transcript verification, and describes speaker-role labels as machine-generated. The full commercial dataset requires a separate agreement. These samples are promising for non-commercial exploratory evaluation but are not approved gold, representative Darija material, or a grant of commercial rights. Inventory: `docs/implementation/evidence/step13-20261028/axondata-inventory.json`.

Follow-up inspection of the two French AxonData DOCX samples found that one exposes an `English transcription` heading without an identified original-language section; the other includes an `Original Transcription` heading. Exact audio alignment, transcript language, completeness, human review and non-commercial rights still require verification. Scoring French speech against translated English text would be invalid.

## Paired five-call result

Both models completed the same five UniData calls locally. Whisper tiny CPU int8 measured WER/CER 0.36511/0.26277; Qwen3-ASR 0.6B CUDA FP16 measured 0.26169/0.17939 against the source-provided references. These references have not been independently verified; the sample is non-commercial, small, and not verified speaker-disjoint. Qwen is a provisional candidate for additional evaluation, while the existing faster-whisper provider remains the operational fallback and default. CPU and GPU latency and Qwen chunking are not directly comparable. The full results and constraints are in STEP13 report section 16.
